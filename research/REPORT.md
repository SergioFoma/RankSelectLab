# Исследование реализаций динамического множества целых ключей с запросами.

![](./pictures/keys_picture.jpg)

## Цель работы.

Исследовать модель запросов на множестве целых ключей, реализованную на различных
структурах данных:
- std::set
- упорядоченный std::vector
- дополненное AVL - дерево
- B - дерево

## Методика измерений

Для выявления преимуществ одной структуры данных над другой в ходе исследования изменялись следующие параметры:

* Размер множеств
* Отношение $\frac{\text{число запросов}}{\text{число вставок}}$
* функция распределения ключей

На каждый эксперимент проводится измерение времени, в течении которого получается
результат обработки последовательности запросов.

Для измерения зависимости скорости обработки от величины $\frac{\text{число запросов}}{\text{число вставок}}$ рассматриваются три соотношения:

**(1.1)** $\frac{\text{число запросов}}{\text{число вставок}}$ = 0.3

**(1.2)** $\frac{\text{число запросов}}{\text{число вставок}}$ = 0.7

**(1.3)** $\frac{\text{число запросов}}{\text{число вставок}}$ = 1

Доля каждого из запросов q, m и n составляет $\frac{1}{3}$ от общего числа запросов.

В качестве размеров множеств были выбраны следующе значения: ```100, 10000, 1000000``` (шаг - множитель 100).
Для нахождения зависимости от размера множества ```N``` выполнялись запросы, количество которых определялось из соотношений `(1.1)` - `(1.3)`, причем для разных
структур данных, с одинаковой мощностью множества ключей, используется одна и та же последовательность запросов.


В качестве последовательности входных данных были выбраны следующие распределения ключей:

- По возрастанию. Сначала вставляются все ключи, потом идут все запросы.
- По возрастанию. Ключи и запросы распределены равномерно в общей последовательности.
- По убыванию. Сначала вставляются все ключи, потом идут все запросы.
- По убыванию. Ключи и запросы распределены равномерно в общей последовательности.
- Случайное. Сначала вставляются все ключи, потом идут все запросы.
- Случайно. Ключи и запросы распределены равномерно в общей последовательности.

В каждой из последовательности входных данных будут присутствовать дубликаты. Их доля от N задана и постоянна - ```35%```

Отличительной особенность B - дерева является то, что оно имеет свой внутренний параметр - степень дерева.
В основной части эксперимента будет выбрано значение ```t = 50```, а в дополнении к исследованию
будет приложена зависимость скорости обработки запросов B - дерева от t.

Для каждого множества ключей мощностью N выборка будет идти из диапазона [-0.5N, 0.5N].

## Асимптотики реализаций

`N` — число ключей в множестве, `k` — число ключей в `(l, r]`, `t` — степень B-дерева.

| Операция                         | `std::set`                           | Упорядоченный `std::vector`             | AVL-дерево | B-дерево       |
|----------------------------------|--------------------------------------|-----------------------------------------|------------|-----------------|
| `k x` — вставка                  | `O(log N)`                           | `O(1)` амортизированно (запись в буфер) | `O(log N)` | `O(t · log_t N)`|
| `q l r` — число ключей в `(l, r]`| `O(log N + k)`, худший случай `O(N)` | `O(log N)` после слияния                | `O(log N)` | `O(t · log_t N)`|
| `m i` — i-й наименьший ключ      | `O(N)`                               | `O(1)` после слияния                    | `O(log N)` | `O(t · log_t N)`|
| `n x` — число ключей меньше `x`  | `O(N)`                               | `O(log N)` после слияния                | `O(log N)` | `O(t · log_t N)`|

## Результаты

### std::set из стандартной библиотеки

При небольшом количестве вставляемых ключей (N ~ 10<sup>0</sup> - 10<sup>2</sup>) показывает
относительно неплохие временные результаты, но является самым медленным алгоритмом среди исследуемых при N > 10<sup>4</sup> ввиду линейной асимптотики при некоторых типах запросов. При N ~ 10<sup>6</sup> обработка входных данных занимает длительно время: порядка ```3 часов```. Границы применимости: 10<sup>0</sup> < N < 10<sup>4</sup>.

### упорядоченный std::vector

Является лучшей структурой данных в случае, когда сначала идет заполнение
множества ключей, а затем последовательные обращения к нему. Максимальное время ожидания исполнения всей последовательности
запросов порядка ```4 минут```. Имеет более низкие показатели на распределениях, где вставка и запросы чередуются.
Обоснованием этому является сортировка и слияние при каждом запросе.
Время работы пропорционально соотношению **$\frac{\text{число запросов}}{\text{число вставок}}$**.

<img src="./pictures/heatmap_SortedVector.png" alt="heatmap SortedVector" width="700">

### avl - tree

Хорошо себя показывает на всех типах входных данных. Максимальное время ожидания исполнения всей последовательности
запросов порядка ```1 секунды```. Особенно выделяется по сравнению с ```std::vector``` и ```std::set``` при работе с распределениям типа, когда вставки и запросы равномерно распределены во входной последовательности. Однако временные показатели чуть больше временных показателей B - дерева. Это связано с постоянным промахом по кешу при обходе дерева. Слабо зависит от соотношения **$\frac{\text{число запросов}}{\text{число вставок}}$**, это хорошо видно по слабому наклону тепловой карты.

### b - tree

Хорошо справляется с большими объемами данных и занимает 1 - ое место при работе с распределениями, в которых вставки и запросы чередуются во входной последовательности. Слабо зависит от соотношения **$\frac{\text{число запросов}}{\text{число вставок}}$**, это хорошо видно по слабому наклону теплой карты. Имеет варьирующийся параметр - степень t.

## Заключение

На входных данных, в которых сначала идет заполнение (вставка ключей), а затем запросы
ко множеству, лучшие показатели имеет ```упорядоченный std::vector```.


```Avl - дерево``` занимает первое и второе места в списке структур данных для поиска в случае, когда вставка ключей и
запросы распределены равномерно (равномерное чередовение).

```B - дерево``` занимает первое место среди исследуемых структур для поиска
при больших объемах данных (N ~ 10<sup>6</sup>) и чередовании вставок с запросами. Для B - дерева получена зависимость
времени работы от степени дерева: при ```5 < t < 20``` видим нисходящий тренд. Это
связано с тем, что при слишком малых t дерево начинает увеличиваться по высоте и быть слабо
отличимым от бинарных деревьев. При ```t > 30``` наблюдается восходящий тренд с небольшими флактуациями. Это объясняется
ростом линейного поиска внутри одного узла. Минимальное значение времени достигается при ```t = 30```.

```std::set``` проигрывает остальным алгоритмам ввиду того,
что выполнение запросов в конечном счете сводится к линейному перебору, в то время как у других
алгоритмов ($\log N$) и быстрее.
